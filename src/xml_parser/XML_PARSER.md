# XML Parser Module

The `xml_parser` module parses PhyloXML files generated by the `data_generation` module and converts them into NumPy arrays suitable for machine learning workflows.

## Overview

The XML parser reads PhyloXML data containing phylogenetic trees with sequences and converts them into structured NumPy arrays with the following fields:

- **`X`**: One-hot encoded sequences shaped `[taxa, length, channels]` (padding and gap channels added when indels enabled during NPY creation).
- **`y_br`**: Branch lengths in fixed 2–4 taxa layouts.
- **`branch_mask`**: Boolean mask for present branches.
- **`y_top`**: One-hot topology indicator.
- **`tree_index`**: Original index from the XML file.

## Usage

### Command-Line

```bash
python -m src.xml_parser --config path/to/your/config.yaml
```

This writes `npy_data/<output_name>.npy` (or to the custom `npy_directory` if specified).

### Programmatic

```python
from src.xml_parser import XMLParser

parser = XMLParser.from_config_file("path/to/config.yaml")
parser.parse_and_write()
```

Or with custom output path:

```python
from pathlib import Path
from src.xml_parser import XMLParser

parser = XMLParser.from_config_file("path/to/config.yaml", output_path=Path("custom_output.npy"))
parser.parse_and_write()
```

## Output Structure

The output NumPy file is a structured array containing one record per tree with the following fields:

### X (Sequences)

Shape: `[taxa, sequence_length, channels]`

Channels:
- `0-3`: One-hot encoded nucleotides (A, T, G, C)
- `4` (optional): Padding channel (`+`, present only when indels are enabled)
- `5` (optional): Gap channel (`-`, present only when indels are enabled)

Example with 3 taxa, 100bp sequences, no indels:
```
shape: [3, 100, 4]
```

Example with 3 taxa, 100bp sequences, indels enabled:
```
shape: [3, 100, 6]
```

### y_br (Branch Lengths)

Shape depends on tree rootedness and taxa count:

**Rooted Trees**:
- 2 taxa: length 2
- 3 taxa: length 6
- 4 taxa: length 10

Branch vectors double each edge to keep stable ordering regardless of where the root lands. Both slots are populated when the root splits a branch.

**Unrooted Trees**:
- 2 taxa: length 1
- 3 taxa: length 3
- 4 taxa: length 5

Branch vectors contain only present edges in deterministic order (no doubling).

### branch_mask

Shape matches `y_br` length.

Boolean array indicating which branch slots were filled in the observed tree. Always `True` for all entries in rooted datasets; for unrooted datasets, marks which edges were actually present.

### y_top

Shape: `[num_topologies]`

One-hot encoded topology indicator. The index of the `1` indicates which topology from the configuration was used for this tree.

### tree_index

Scalar integer.

Original index of the tree in the PhyloXML file (0-based).

## Branch Representation Details

### Rooted Trees

Branch edges are doubled to maintain consistent ordering across all possible root placements. This ensures that the model can learn robust branch length predictions.

**2 taxa rooted example**:
- `y_br`: `[edge_to_taxon1_left, edge_to_taxon1_right]`
- When root splits the edge: both slots are populated with the resulting child edge lengths

**3 taxa rooted example**:
- `y_br`: `[edge1_left, edge1_right, edge2_left, edge2_right, edge3_left, edge3_right]`
- Each split edge has paired slots

**4 taxa rooted example**:
- `y_br`: `[edge1_left, edge1_right, edge2_left, edge2_right, edge3_left, edge3_right, edge4_left, edge4_right, edge5_left, edge5_right]`

### Unrooted Trees

Branch vectors contain only observed edges in deterministic order without doubling.

**2 taxa unrooted example**:
- `y_br`: `[single_edge]`
- `branch_mask`: `[True]`

**3 taxa unrooted example**:
- `y_br`: `[edge1, edge2, edge3]`
- `branch_mask`: `[True, True, True]`

**4 taxa unrooted example**:
- `y_br`: `[edge1, edge2, edge3, edge4, edge5]`
- `branch_mask`: `[True, True, True, True, True]`

## Limitations

- Only supports 2–4 taxa datasets
- Datasets with more than 4 taxa are not supported by the NumPy writer
- Requires corresponding configuration file for metadata (taxa labels, sequence length, etc.)

## Key Classes

### `XMLParser`

Main parser class:

```python
from src.xml_parser import XMLParser

parser = XMLParser.from_config_file("path/to/config.yaml")
datasets = parser.parse()  # Returns list of dataset records
parser.parse_and_write()   # Writes to NPY file
```

### `Extractor`

Extracts tree data from PhyloXML:

```python
from src.xml_parser.extractor import Extractor

extractor = Extractor(config)
tree_examples = extractor.extract()
```

### `NPYWriter`

Converts extracted data to NumPy format:

```python
from src.xml_parser.writers import NPYWriter

writer = NPYWriter(config)
dataset = writer.write(tree_examples, output_path)
```

## Integration with Data Generation

The typical workflow is:

1. Create a configuration file (see [Data Generation Module](../data_generation/DATA_GENERATION.md))
2. Generate PhyloXML:
   ```bash
   python -m src.data_generation --config config.yaml
   ```
3. Parse to NumPy:
   ```bash
   python -m src.xml_parser --config config.yaml
   ```
4. Load and use in your pipeline:
   ```python
   import numpy as np
   data = np.load("npy_data/output_name.npy")
   ```
